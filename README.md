# 通用提示词架构师 Skill

**版本：V1.0** · **语言：简体中文（可处理繁体中文与中英混合输入）** · **格式：平台中立 Markdown** · **许可：非商业使用，商业用途须另行授权**

本项目提供一套通用的提示词架构师规则：将用户自然、零散、口语化、持续变化的表达整理成准确、完整、逻辑严谨、可交给目标 AI 使用的提示词，并通过独立模式维护 Skill 自身、讨论和纠正 AI 的执行偏差。

> **重要定位：** 模式一只生成和迭代提示词，不执行提示词描述的原始任务。该 Skill 不等同于自动化代理，也不保证所有 AI 平台都能自动加载或完全一致地执行规则。

## 核心能力

- **模式一——生成提示词：** 理解用户意图、整理上下文、检查逻辑、构建并迭代自包含提示词。
- **模式二——编辑 / 升级 Skill：** 检查、维护、优化和发布本 Skill 文件。
- **模式三——讨论 / 纠错：** 暂停前两种工作，讨论理解偏差、角色越界、规则冲突和纠正办法。
- **中文预检查：** 检查中文表达与逻辑；明显表达问题静默修正，方向性歧义才询问，次要缺失以明确假设处理。
- **跨平台设计：** 使用普通 Markdown 和明确文字规则，不依赖某个特定平台的专有按钮或 API。

## 快速开始

1. 下载或克隆本仓库。
2. 将根目录的 `SKILL.md` 提供给目标 AI，确保 AI 能读取完整文件。
3. 首次加载且未选择模式时，AI 应展示三模式菜单并等待选择。
4. 后续在用户消息开头使用 `1`、`2` 或 `3` 选择模式；规则详见 `SKILL.md` 第 4 节。

### 三种模式

| 前缀 | 模式 | 用途 |
|---|---|---|
| `1` | 生成提示词 | 把需求整理成提示词，不执行原始任务 |
| `2` | 编辑 / 升级 Skill | 维护本 Skill 本身 |
| `3` | 讨论 / 纠错 | 暂停其他工作，讨论 AI 的理解和执行偏差 |

示例：

```text
1 请把我下面的想法整理成一份网站开发提示词……
2 请检查当前 Skill 的规则冲突，并提出修订建议……
3 你刚才执行了原始任务，而不是生成提示词，请分析偏差……
```

## 数字前缀的重要副作用

本项目采用用户明确选择的**强首字符协议**：忽略消息开头的空白后，只检查第一个非空白字符。ASCII `1/2/3` 和全角 `１/２/３` 触发相应模式，不做语义豁免。因此：

- `2026 年资料` 会触发模式二；
- `3月安排` 会触发模式三；
- `12 个样本` 会触发模式一；
- `1. 第一项`、`2) 第二项`、`3、第三项` 也会触发对应模式。

若要发送普通数字资料而不切换模式，请先加文字标签，例如 `资料：2026 年资料`、`补充：3月安排` 或 `编号：12 个样本`。不要在数字前使用标点或项目符号来期待系统跳过它们。

## 兼容性与限制

- 这是平台中立的 Markdown 规范，不是某个平台专属的可执行插件包。
- 平台必须先能读取 `SKILL.md`，规则才有机会生效；Markdown 文件无法强迫未读取它的 AI 自动执行。
- 不同模型对长上下文、状态保持、Unicode 字符和规则遵循的支持可能不同。请使用独立验收测试验证目标平台。
- 若平台无法保持跨轮状态，或对 Unicode 空白字符处理不同，应如实说明限制，不应伪称规则已被可靠执行。
- 本 Skill 不主动搜索其他对话或个人资料，也不管理 AI 账号原生记忆。
